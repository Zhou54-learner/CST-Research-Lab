# 协作与数据协议 v0.1

本协议服务于学习和可复用实验。首版使用普通文件与命令行；输入输出约定以后可直接用于 MCP 包装，不提前建立服务框架。

## 1. 从哪里接续

`README.md` 是入口；`CST学习路线.md` 说明目标；`learning-state.json` 记录当前任务、下一步、项目状态、能力依据和学习观察。新会话读取这些内容与当前项目说明即可继续。HTML 是同一状态与实验记录的展示，不单独保存另一份进度。

仪表盘首页围绕当前学习行动组织。`current.project_id` 指向当前准备或进行的学习项目，`current.status` 说明任务准备状态，`task_file` 有真实任务说明后才填写。`review_items` 保存待回访问题及下一步，无实际记录时留空。环境验收属于 `INFRA`，不计入学习实验或项目完成数；可迁移能力与项目完成分别统计，不生成总掌握百分比。

文件分工：`docs/` 放约定和环境报告，`tools/` 放可复用操作，`runs/` 放不可混淆的每次运行；项目开始后在 `projects/<编号>/` 集中目标、模型与说明。仅在真实内容出现时增加分类。

## 2. 任务和运行约定

普通学习任务用项目说明描述目标、约束、交付和这次亲自练习的环节，无需固定问卷。可执行任务使用 JSON，首版运行记录格式如下：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 当前为 1，表示数据格式版本 |
| `run_id` / `project_id` | 唯一运行编号、所属项目；基础设施使用 `INFRA` |
| `status` | `running`、`passed` 或 `failed`；意外中断保留 running，检查时明确提示 |
| `source` | `analytic`、`cst`；未来增加 `surrogate` 时仍与真实数据区别 |
| `task` | 目标、参数及单位、计算限制、事先声明的判据 |
| `implementation` | 工具源码 SHA-256、Python 版本；CST 运行记录安装版本 |
| `started_at` / `finished_at` | 带时区的开始和结束时间 |
| `metrics` / `error` | 指标、错误原因；失败不伪装成成功 |
| `artifacts` | 相对仓库路径及文件摘要，链接原始数据、模型、History 与日志 |

每次运行生成一个新目录，保存 `run.json` 和必要产物。重试不覆盖上一轮。源代码指纹与归档的执行脚本一起保留，使初次提交之前的实验也可追溯。数值列包含单位，复数结果保存实部和虚部；图表从原始数据生成。

运行证据在 Git 中保留原始字节，不自动转换换行符，确保另一台机器取回后仍能核对文件摘要。

首版工具：`doctor` 检查环境；`smoke` 执行最小闭环并更新页面；`refresh` 重建页面；`check` 检查状态、运行证据与页面一致性。工具返回零表示所请求操作通过，非零表示失败。外层 agent 可读取 JSON 判断下一步，不需要解析自然语言输出。

## 3. 人、AI 与记忆

学习者负责当前训练的设计选择、关键操作和解释；AI 提供适量教学、环境维护和记录整理。进入 P8 后，任务范围和预算内的调度可连续执行，以运行证据复盘。实际调度能力与 MCP 在对应阶段搭建，当前只准备通用文件接口。

能力状态：`未观察`、`提示下完成`、`可独立完成`、`可迁移`。用户自述作为起点说明，实际能力按后续作品和独立表现确认；基础设施验收单独记载。

记忆条目包含来源、观察、暂时解释、建议练习及后续变化。只记录有教学价值的内容，正向进步也更新；用户能纠正或删除。首次只保存用户已明确表达的学习偏好，不编造盲区。静态页面不监听操作，所有更新发生在明确的工作会话中。

## 4. 比较与版本

比较前说明改变了什么，保留共同条件和原始结果。页面只把条件可比的运行放在同一图中；解析基线明确标注。工具、指标或物理条件改变后记录版本，不让一次实现变化混入不明来源的“提升”。

首版可展示指标、关键曲线、耗时和失败；人工介入量只在实际记录后显示，不根据自动化脚本推断为零。研究设计数据与系统执行证据通过 run_id 关联，为 P8–P9 留下可用素材，但不要求早期逐步记录全部思考。

## 5. 实际存储与同步

Git 同步项目源文件、状态与有用运行成果。本地配置 `.local/config.json` 保存 CST 安装路径；`.venv/` 可重建；求解临时目录只作工作区。每次成功测试把模型和小型结果复制到 `runs/` 后再提交，避免只有摘要没有证据。

当前工作目录位于 OneDrive。运行中的 CST 工作文件放在本机临时目录，完成并关闭后再归档到项目，以减少求解期间外部同步干扰；Git 提交和推送才是本项目的显式版本记录。未来大数据备份按实际体量选择，不能只靠 README 声称已备份。
